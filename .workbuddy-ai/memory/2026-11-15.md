## Global /bug reporting feature

- New `handlers/bug.py`: `/bug <desc>` works in DMs + any group, forwards a Markdown report to `BUG_ADMIN_ID` (falls back to `BOT_OWNER_ID`, both in `config.py`). Report includes description, display name/@username, copyable inline-code user ID, chat title + ID, MYT timestamp, and ready-to-copy `/banbug <id>` + `/ban <id>` lines. Owner-only `/banbug` / `/unbanbug` accept a numeric ID, mention or reply.
- New `stores/bug_store.py`: Redis JSON list `bug_banned_users`; atomic `SET NX EX` cooldown key `bug_cooldown:<uid>` (default 600s, `BUG_COOLDOWN_SECONDS`, min 60); Redis set `bug_announced_chats` claimed with atomic `SADD` for one-time group notice. All checks fail closed on Redis errors.
- **Important PTB detail discovered:** `Application.process_update` runs at most ONE handler per group. The old group-1 registration had `filters.ALL` `seen_user_tracker` first, so `command_stats_tracker` never ran. Fixed by consolidating into `handlers/tracking.passive_tracker` (single `filters.ALL` handler in group 1, dispatches 3 jobs with `asyncio.gather(return_exceptions=True)`). This also hosts `bug_announcement_tracker`.
- `/help` "Other" page documents `/bug`; CHANGELOG.md gained a real `v1.1.0` release whose `/log` output contains the `/bug` announcement bullet (template still uses inert `v1.0.3` inside an HTML comment, so no collision). `/status` now shows bug destination, ban count, announced-group count. README documents the whole flow.
- Tests: `tests/test_bug_reporting.py` (FakeRedis + Telegram fakes), updated `tests/test_registry.py` for 40 commands and single group-1 handler. Full suite = **47 tests OK**; real PTB Application builds with 48 handlers (groups -1:1, 0:45, 1:1, 2:1). Verified generated Redis commands: `SET key 1 NX EX 600`, `SADD ...`.
- User preference: **no "one report per 10 minutes" warning in any user-facing Telegram text**. Removed it from the one-time group notice (`BUG_ANNOUNCEMENT_TEXT`), the `/bug` usage reply and the `/help` Other page. The Redis rate limit is still enforced (users only see "Please wait Xs" when they actually hit it); README/CHANGELOG keep the technical documentation of the limit.
