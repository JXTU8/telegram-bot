# 2026-11-16

## /ask error-handling overhaul

- **Root cause found and proven with real `google.genai.errors` objects:** a `ClientError(429)` string is `429 RESOURCE_EXHAUSTED. {... 'message': 'The model gemini-3.5-flash-lite is overloaded'}`. The old `if "model" in str(e)` branch ran before the rate-limit branch, so 429/503 high-demand failures told users the MODEL NAME was wrong. A 503 literally says "The model is overloaded".
- New `handlers/ask_errors.py` (no Telegram/Gemini/Redis imports → purely unit-testable): `classify_ask_error(exc) -> AskFailure(category, message, retryable, silent)`. Pulls HTTP status from `.code` / `.response.status_code` / `__cause__` chain / narrow 3-digit regex; each category has its own `_handle_*` function in a priority-ordered tuple. Busy is checked before auth/model, and text markers are ignored when a contradictory status (400/401/403/404/408/504) is present.
- Categories: busy (429/503/500/502), timeout, network, safety, auth_key (401), auth_permission (403), model (404), bad_request (400), empty_answer, telegram_too_long, not_modified (silent), unknown. Distinct 401 vs 403 messages.
- `handlers/ai.py`: `_gemini_complete` now inspects `prompt_feedback.block_reason` / `candidate.finish_reason` BEFORE reading `.text` (which can raise on blocked content) and raises `AskSafetyBlocked` / `AskEmptyAnswer`. `/ask` with empty, whitespace or punctuation/emoji-only prompt gets a specific hint. Web search failure is now non-fatal (`use_search` degrades gracefully). Answers are split with UTF-16-aware `build_answer_messages()` capped at 3900 units (Telegram limit 4096). Overflow failures notify the user instead of silently truncating; retryable failures release the 3 s per-user cooldown.
- Tests: new `tests/test_ask_errors.py` (real SDK errors, classification matrix, chunking incl. emoji-only answers, empty prompts, end-to-end 429 flow and search-failure fallback). Suite now **71 tests OK**.
